# Отчет о проведенном тестировании

## Краткое описание
В рамках курсового проекта было проведено автоматизированное тестирование веб-сервиса «Путешествие дня», который позволяет приобрести тур двумя способами: обычная оплата по дебетовой карте и выдача кредита по данным банковской карты.
Тестирование проводилось с использованием UI-автотестов (Selenide) и проверок записей в СУБД (MySQL).

## Количество тест-кейсов
Всего было автоматизировано **33 тест-кейса**, покрывающих позитивные сценарии (Happy Path), сценарии отказа банка (DECLINED) и валидацию полей формы (негативные сценарии).

## Результаты прохождения тестов
*   **Успешно пройдено:** 30 тестов (90.9%)
*   **Не пройдено:** 3 теста (9.1%)

*Примечание: 3 упавших теста обнаружили реальные баги в тестируемом приложении (SUT). Тесты написаны корректно и упали именно из-за дефектов в коде SUT.*

## Найденные дефекты (Баг-репорты)
В ходе тестирования были выявлены следующие баги (оформлены в виде Issue в GitHub):
1.  **[Баг] При оплате картой DECLINED отображается уведомление об успехе** (Критический). Бэкенд корректно записывает статус `DECLINED` в БД, но фронтенд показывает зеленое уведомление «Успешно».
2.  **[Баг] Отсутствует валидация поля «Владелец»** (Высокий). Поле принимает кириллицу, цифры и спецсимволы, пропуская невалидные данные в банк.
3.  **[Баг] Поле «Месяц» пропускает значение «00»** (Высокий). Отсутствует проверка на логически невозможный месяц.
4.  **[Баг] Номер карты «0000 0000 0000 0000» проходит валидацию** (Средний). Фронтенд пропускает карту из нулей, банк отклоняет операцию.

## Общие рекомендации
1.  **Исправить логику работы фронтенда с ответами API:** Синхронизировать отображение уведомлений с реальными статусами, которые возвращает бэкенд (особенно для статуса `DECLINED`).
2.  **Добавить фронтенд-валидацию:** Усилить проверки на стороне клиента (регулярные выражения) для полей «Владелец», «Месяц» и «Номер карты», чтобы не отправлять заведомо невалидные данные на сервер.
3.  **Добавить API-тесты:** В будущем рекомендуется покрыть тестами сами эндпоинты, чтобы не зависеть от нестабильного UI.
