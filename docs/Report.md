# Отчет о проведенном тестировании

## Краткое описание
В рамках курсового проекта было проведено автоматизированное тестирование комплексного веб-сервиса «Путешествие дня», который предлагает пользователям два способа приобретения тура:
1. Обычная оплата по дебетовой карте.
2. Выдача кредита по данным банковской карты.

Тестирование проводилось на трех уровнях:
*   **UI-уровень:** проверка взаимодействия пользователя с веб-интерфейсом (Selenide).
*   **API-уровень:** эмуляция запросов, отправляемых браузером при заполнении формы (RestAssured).
*   **Уровень данных:** проверка корректности внесения информации в СУБД (MySQL/JDBC).

## 2. Результаты тестирования
Всего было автоматизировано **36 тест-кейсов** тест-кейсов, покрывающих позитивные сценарии (Happy Path), отказы банка (DECLINED) и негативные сценарии валидации полей.


## Результаты прохождения тестов
*   **Успешно пройдено:** 29 тестов (76%)
*   **Не пройдено:** 9 теста (14%)

*Примечание: 9 упавших тестов обнаружили реальные баги в тестируемом приложении (SUT). Тесты написаны корректно и упали именно из-за дефектов в коде SUT.*

## 3. Найденные дефекты (Issues)
В ходе тестирования были выявлены следующие баги (оформлены в виде Issues в GitHub):

1.  **[Критический] Неверное отображение статуса оплаты для карты DECLINED** — `[https://github.com/Ilich8603/javaAQAmid_aqa-qamid-diplom/issues/1]`
    *   *Описание:* Бэкенд корректно записывает статус `DECLINED` в БД, но фронтенд показывает уведомление «Успешно. Операция одобрена банком». Пользователь вводится в заблуждение.
2.  **[Высокий] Отсутствует валидация поля «Владелец»** — `[https://github.com/Ilich8603/javaAQAmid_aqa-qamid-diplom/issues/2]`
    *   *Описание:* Поле принимает кириллицу, цифры, спецсимволы и одно слово (например, `ИВАН`, `IVAN 123`). Данные уходят в банк.
3.  **[Высокий] Поле «Месяц» принимает значение «00»** — `[https://github.com/Ilich8603/javaAQAmid_aqa-qamid-diplom/issues/3]`
    *   *Описание:* Отсутствует проверка на логически невозможный месяц. Запрос отправляется на бэкенд.
4.  **[Средний] Номер карты «0000 0000 0000 0000» проходит валидацию** — `[https://github.com/Ilich8603/javaAQAmid_aqa-qamid-diplom/issues/4]`
    *   *Описание:* Фронтенд не блокирует карту из нулей, отправляя запрос в банк (где он отклоняется).

## 4. Общие рекомендации
Для повышения качества продукта и устранения выявленных дефектов рекомендуется:
1.  **Исправить обработку ответов API на фронтенде:** синхронизировать отображение UI-уведомлений с реальными статусами, которые возвращает бэкенд (особенно для статуса `DECLINED`). Ошибка критична, так как напрямую влияет на бизнес-процессы и доверие клиентов.
2.  **Усилить фронтенд-валидацию:** добавить регулярные выражения (RegEx) для проверки полей «Владелец» (только латиница, пробел, дефис, минимум 2 слова), «Месяц» (диапазон 01-12) и «Номер карты» (запрет на карты из нулей).
3.  **Внедрить проверку карт на стороне банка:** карты, не входящие в тестовый набор (кроме APPROVED и DECLINED), должны корректно отклоняться на стороне шлюза, а фронтенд должен отображать соответствующую ошибку.
4.  ****Поддерживать актуальность API-тестов:** использовать их в CI/CD для быстрой проверки интеграции фронтенда и бэкенда.**
