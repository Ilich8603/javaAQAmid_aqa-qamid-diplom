# Отчет по итогам автоматизации

## Что было запланировано и что реализовано
**Запланировано:**
*   Автоматизация UI-тестов для формы «Купить» и «Купить в кредит».
*   Проверка записей в БД (MySQL) с помощью JDBC/DbUtils.
*   Настройка генерации отчетов Allure.
*   Написание позитивных и негативных сценариев (валидация полей).

**Реализовано:**
*   ✅ Настроен проект на Java 11 + Gradle.
*   ✅ Развернута БД в Docker (MySQL).
*   ✅ Написаны UI-тесты (Selenide) — 33 шт.
*   ✅ Написаны проверки БД (статусы операций, суммы, связи заказов).
*   ✅ Интегрирован и настроен Allure для наглядной отчетности.
*   ✅ Найдены реальные баги в приложении и оформлены Issue.
*   ✅ API-тесты: Реализованы с использованием RestAssured для проверки эндпоинтов `/api/v1/pay` и `/api/v1/credit`.
*   ✅ CI/CD: Настроен GitHub Actions workflow (`.github/workflows/build.yml`). При каждом коммите автоматически поднимается MySQL в Docker, запускается SUT и прогоняются все тесты.

## Причины, по которым что-то не было реализовано
*   **Тесты для обеих форм валидации:** Валидация полей на формах «Купить» и «Купить в кредит» идентична на фронтенде, поэтому для экономии времени тесты валидации были написаны только для одной формы, а бизнес-логика (оплата/кредит) проверена для обеих.

## Сработавшие риски
1.  **Нестабильность банковского симулятора:** Общий сервер иногда отвечает с задержкой. *Решение: увеличены таймауты ожидания в Selenide (использован `Duration` в ассертах).*
2.  **Сложности с локаторами:** Из-за использования React (динамической верстки) и отсутствия `name`/`id` у некоторых элементов, пришлось использовать XPath и кастомные методы поиска.
3.  **Реальные баги в SUT:** Некоторые негативные тесты (на валидацию) падают, так как SUT пропускает невалидные данные. Это не риск автоматизации, а ожидаемый результат тестирования, который привел к созданию баг-репортов.

## Общий итог по времени
*   **Запланировано:** ~24-30 часов.
*   **Потрачено:** ~30 часов.
*   **Обоснование расхождения:**
    *   Потребовалось дополнительное время на отладку локаторов (из-за особенностей верстки) и настройку ожиданий (ожидание исчезновения/появления скрытых уведомлений).
    *   Время на написание баг-репортов и анализ логов БД при проверке упавших тестов.
    *   Дополнительное время потребовалось на настройку CI (GitHub Actions) и написание API-тестов (RestAssured), которые изначально не были в базовом плане
